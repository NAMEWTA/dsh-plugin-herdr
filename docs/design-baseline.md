## 1. 执行结论：不要继续做“更大的 Herdr 页面”

### 1.1 推荐产品定位

将当前单一用途插件重构为：

**一个独立维护的模块化工作台，拥有统一设计系统、模块注册机制、权限与任务基础设施；Herdr 控制台是第一个业务模块。**

这不是把文件移到 `modules/herdr` 后继续让每个页面直接调用 DSH 和 Herdr，也不是先建设一个复杂插件市场。首发采用**模块化单体**：同一发行包、明确依赖边界、按模块注册与懒加载，后续确有需求时再增加独立进程隔离。

### 1.2 九项核心决定

| 决策 | 推荐结论 | 对实现的约束 |
|---|---|---|
| 产品独立化 | 与原插件上游脱钩，拥有自己的仓库、品牌、版本、发布与路线图 | 不再自动同步上游；保留必要版权与来源记录 |
| 运行形态 | 首发仍提供 DSH 插件入口，核心不依赖 DSH | “独立项目”不伪称“首发可脱离 DSH 运行” |
| 模块化 | 平台核心 + SDK + Herdr 模块 + 宿主适配器 | 核心代码不得识别 Herdr 特有工作区或 pane |
| 兼容策略 | 旧导出、路由、工具命名、配置结构与存储格式不兼容 | 不建设旧 API shim、双写或多代界面 |
| 前端 | React 19 系列，与目标宿主使用同一 React 实例 | 当前已经是 React；重点是边界与一致性 |
| UI 体系 | shadcn/ui + Base UI 单一原语基座 + Tailwind CSS 4 + 自有 UI 包 | 不混搭 Ant Design、MUI、Radix 与 Base UI 的同类组件 |
| 数据 | 后端权威读模型 + TanStack Query 前端缓存 + 独立终端流 | 不把终端字节流放进普通 React 全局状态 |
| 首页 | 待处理事项优先，而不是大面积 CPU 仪表或终端墙 | 连接可信度、待介入、异常、未读完成、工作区优先 |
| 扩展节奏 | 先完成一个真实模块和一个验证用模块 | 不在首发上线任意远程代码安装与插件市场 |

以上为本次设计选择，不是“行业唯一最佳方案”。React 版本事实及 UI 基座现状分别见 [S02] [T01] [T02]。

### 1.3 成功的直观判断

用户进入工作台后，应该立即知道“连接是否可信、哪里需要我、我正在操作哪台主机的哪个工作区”；进入 pane 后，应清楚看到“只读还是可输入、当前控制权属于谁、断线会发生什么”。开发者新增第二个业务模块时，不需要修改 Herdr、平台导航组件或复制一套设置页。发布者可以不跟随原插件上游发布节奏，独立构建、测试和交付。

## 2. 用户目标、约束与不做的事

### 2.1 角色与核心任务

| 角色 | 任务 | 当前重构要解决的问题 |
|---|---|---|
| 单人多 Agent 使用者 | 同时观察多个工作区，及时处理等待输入 | 重要事项被普通状态和终端内容淹没 |
| 深度终端用户 | 在不干扰现有 TUI 的情况下观察、接管与输入 | 多窗口生命周期与控制权容易产生误解 |
| 项目维护者 | 管理模块、环境、版本、诊断和发布 | 功能代码与宿主细节、UI 样式耦合 |
| 只读观察者 | 看见状态但不能发键或关闭工作区 | UI 禁用按钮不能替代服务端授权 |
| 后续模块开发者 | 增加通知、任务、文件审查等功能 | 不能让每个新增模块重新发明导航、权限和样式 |

“角色”首先是能力集合；首发不强行引入独立账号系统。DSH 模式通过宿主身份映射能力，身份缺失或不可信时拒绝访问敏感接口，而不是默认管理员。

### 2.2 首发范围

首发包含平台壳层、受控模块注册、统一设置与命令入口、Herdr 环境诊断、真实状态总览、待处理队列、工作区/标签/pane 管理、Agent 启动、会话绑定、终端观察和显式控制、基本审计及发行质量门禁。功能在能力不足时明确降级，不使用未公开接口伪装成功。

不在首发承诺：重写 Herdr 终端复用器、替换 DSH 全部聊天产品、多租户 SaaS、第三方任意代码市场、工作流 DAG 引擎、自动云隧道、公网免配置开放、所有 Agent 的结构化聊天、全量历史终端录像、原生 Windows 全覆盖、原包无感升级。

### 2.3 对“独立”的默认解释

本设计默认“上游”指原 `sunny0826/dsh-plugin-herdr`，而不是所有开源依赖。DSH 与 Herdr 仍是明确声明的外部集成。要进一步实现“生产运行完全不依赖 DSH”，必须交付独立服务端、认证、静态资源托管、升级与进程管理；该能力列为后续独立交付项，不能仅凭目录命名宣称完成。

## 3. 当前项目技术审查

### 3.1 已有基础与必须保留的成果

当前包已有 React 19.2.8、TypeScript、Zod、xterm.js、Node 24 基线，已有 `contracts/core/host/web` 分层以及事件、终端会话、环境检测等子目录。不能把它描述为“没有架构、没有测试、需要从非 React 迁移”。[S02] [S07] [S08]

已有质量流水线覆盖构建、类型检查、生成协议漂移、单元测试、打包检查、DSH Web 浏览器冒烟和真实 Herdr 集成。配置中的 DSH 验证矩阵为三个预发布版本，Herdr 集成矩阵为 0.9.0 与 0.9.3；这描述的是当前流水线，不是未来必须保留的旧版本范围。[S09]

现有终端管理器已经包含 observe/control 区分、每 pane 控制冲突、配额、generation/seq、全帧与差量回放、断线宽限和真实进程退出后释放配额等机制。重构可以更换实现，但不能删除这些约束以换取“代码更简单”。[S10]

### 3.2 具体发现与处理策略

| 编号 | 证据与现状 | 风险或问题 | 重构处理 |
|---|---|---|---|
| A01 | 当前已使用 React，见 package.json | 把重构误解为框架替换会错失主要问题 | 保留 React，重建模块、组件、状态和协议边界 |
| A02 | `web/styles.ts` 约 91,351 字节，运行时注入大段样式 | 样式所有权、复用及跨模块维护成本高 | 设计 token + UI 包 + 模块局部 CSS；拒绝全局样式副作用 |
| A03 | `web/logic.ts` 约 61,477 字节，混合排序、状态、轮询、交互模型 | 大型通用文件重新聚合职责 | 按领域、查询、交互拆分；不是机械按行数分文件 |
| A04 | `session-list-branding.ts` 读取 `__reactFiber` 并匹配宿主类名/标题 | 依赖私有实现；可能错误关联同名前缀会话 | 使用公开槽位与稳定 session ID；无槽位则不装饰宿主列表 |
| A05 | UI 纯逻辑存在从 host 路径导入类型 | 编译层面可行，但架构边界不清晰 | 环境中立类型移入模块 contracts；Web 禁止导入 host |
| A06 | app.tsx 同时负责槽位、模式、品牌、生命周期等接入 | 功能模块与宿主集成可进一步隔离 | DSH adapter 接公开服务，Herdr Web 只接模块 API |
| A07 | 新旧状态映射函数并存，旧映射存在“其他→done”路径 | 未来调用者可能重引入 unknown 误报 | 单一状态映射，逐调用点迁移测试；不声称目前所有界面都有此 bug |
| A08 | 现有样式已使用宿主 token | 并非没有主题，而是主题所有权依赖宿主 | 自有语义 token，宿主通过显式桥接映射 |
| A09 | dashboard DTO 已有 stale、采样时间、collector 状态 | 新 UI 若只展示数字，可能丢失数据可信度 | 保留并放大 freshness/coverage，而非把未知填 0 |
| A10 | 原 package 元数据已是 NAMEWTA，但 GitHub 仍为 fork | 代码归属信息更新不等于仓库关系独立 | 新建独立仓库或确认平台支持的脱离流程，分别验收 |
| A11 | README 与 PR 合并状态不同步 | 使用说明与真实代码产生偏差 | 文档检查、证据索引、版本发布清单同步 |
| A12 | 基线提交修复零参数 RPC 描述符错误 | 类型声明与生成协议、客户端调用可能漂移 | 合同单源、真实生成物 arity 回归；该 bug 在本基线已修复 |

### 4.3 四类可复用的产品模式

**模式一：待处理队列，而不是状态墙。** Collie、Portal、HQ 和 Remote 从不同角度突出人工介入。对本项目的结论是建立统一 AttentionItem：需回复、操作失败、状态异常、完成未读分别呈现。不要把所有 blocked 标成红色故障，也不要把每次心跳变成通知。[R02] [R04] [R05] [R13]

**模式二：同一任务有多种视图。** 终端负责保真与兜底，结构化对话负责可读性，两者必须指向可证明属于当前 pane occupant 的会话。不能因为某个目录出现一个新 JSONL，就认定它属于当前 Agent。[R01] [R03] [R14]

**模式三：主机/工作区范围始终可见。** 手机聚合和跨主机看板显示出一个重要风险：相同的 `w1:p1` 在不同主机并不是同一个资源。本项目应从第一版数据模型就采用复合身份，即便首发仅接一台本机。[R10] [R13]

**模式四：安全语义进入界面。** 可输入的 Web 终端拥有高权限，不是普通只读 dashboard。接管、发送、关闭、配对撤销必须在界面和服务端同时表达；“只在本地监听”不能替代认证和来源验证。[R02] [R14] [T06] [T07]

### 4.4 设计系统层面的观察

`devswha/herdr-web-ui` 的 DESIGN 强调一套机器可读 token、亮暗主题对应层级、舒适/紧凑密度，以及把状态色与主要操作色分开。这些是可借鉴的组织方法，不应复制其主题表、品牌或装饰。该文件本身同时描述基础主题与后续默认主题变化，也说明不能仅凭一段开头文字给产品贴固定配色标签。[R01]

本项目采用中性表面与单主色，状态使用独立语义；首页克制、详情信息丰富。首发不建设数十套皮肤，优先确保同一状态在仪表盘、列表、抽屉、终端标题栏和通知中含义一致。

### 4.5 调研结论到需求的映射

| 研究发现 | 转化为本项目要求 | 优先级 |
|---|---|---|
| 待人工介入比总 Agent 数更有行动价值 | ATT-01 至 ATT-06：统一待处理队列、原因与跳转 | P0 |
| 终端不是聊天的可替代实现 | TER-01 至 TER-10：安全终端；EXT-01：可验证聊天适配 | P0 / P1 |
| 多主机重复 ID 与局部故障普遍存在 | DAT-01、DAT-04：复合身份与局部降级；EXT-02 多主机 | P0 模型 / P1 功能 |
| 资源数字的归属容易误导 | HER-08：明确进程、采样窗口与未知值 | P0 基础 / P1 细化 |
| 第三方库不会自动带来统一设计 | UI-01 至 UI-10：自有 token、组件准入和跨入口测试 | P0 |
| 终端输入等同高权限操作 | SEC-01 至 SEC-09：服务端能力检查、审计、来源校验 | P0 |
| 私有接口会将项目重新绑回上游 | ARC-01 至 ARC-07：公开契约、适配层、静态边界 | P0 |

## 5. 产品蓝图与信息架构

### 5.1 三层导航，不把全部功能挤进 Herdr

```text
工作台（产品层）
├─ 首页：各模块贡献的摘要与待处理事项
├─ Herdr（业务模块一）
│  ├─ 总览
│  ├─ 待处理
│  ├─ 工作区
│  ├─ Agents
│  ├─ 活动
│  └─ 环境与连接
├─ 后续业务模块：任务 / 文件审查 / 通知集成 / 其他
└─ 设置（平台层）
   ├─ 外观、语言与密度
   ├─ 模块管理
   ├─ 权限与安全
   ├─ 诊断与数据
   └─ 关于、许可证与更新
```

工作台“首页”与 Herdr“总览”不是同一个路由。只有一个业务模块时，可默认打开 Herdr 总览，但平台组件不得包含 `if module === 'herdr'` 的专用业务分支。后续通知渠道可成为平台通知服务的扩展，而不是继续长在 Herdr 页面内部。

### 5.2 上下文模型

全局上下文显示运行位置与当前身份；模块上下文显示目标连接和 Herdr session；页面上下文显示 workspace、tab、pane。DSH 对话 ID 与 Herdr session ID 必须是不同字段，名称也不能混用为模糊的 `sessionId`。

筛选器改变“显示范围”，不自动改变终端输入目标。打开新的工作区后，旧输入草稿不自动发送给新 pane。全局命令面板执行前显示完整目标，危险动作必须再次验证对象及版本。

### 5.3 关键路由

| 路由逻辑名 | 内容 | 页面刷新/深链要求 |
|---|---|---|
| `home` | 平台摘要 | 宿主支持深链时映射公开路由，否则使用受控内部路由 |
| `herdr.overview` | 连接状态、待处理、工作区摘要 | 保留筛选范围和视图偏好 |
| `herdr.attention` | 待处理队列与详情 | 可定位资源；失效资源有明确页面 |
| `herdr.workspaces` | 工作区列表/卡片 | 搜索、状态、排序可恢复 |
| `herdr.workspace.detail` | 工作区、tabs、panes 主从视图 | 使用编码后的复合资源引用 |
| `herdr.agents` | 跨工作区 Agent 列表 | 过滤不等于更改运行状态 |
| `herdr.activity` | 当前运行事件与审计检索 | 缺失区间明确标记 |
| `herdr.environment` | 环境、协议、能力与连接诊断 | 不执行隐式安装 |
| `settings.modules` | 模块状态、启停和依赖 | 服务端返回实际状态 |

嵌入 DSH 时，不能假定宿主允许随意接管浏览器 history。适配器优先使用公开导航接口；不存在时内部使用 memory router，并仅在受支持入口保存状态。

## 6. 独立化方案：仓库、产品、运行时分别验收

### 6.1 独立化的四个维度

| 维度 | 首发目标 | 不是目标 |
|---|---|---|
| 代码与仓库 | 自有独立仓库、分支规则、问题跟踪、贡献规范 | 擦除原作者事实或许可证 |
| 产品与发行 | 自有包名、图标、文档、版本、更新源与发布凭据 | 借原上游 release 下载构件冒充本项目产物 |
| 架构 | 核心与业务模块不依赖 DSH 私有实现；Herdr 协议封装在 adapter | 重写所有依赖、放弃正常安全更新 |
| 运行 | 首发 DSH adapter；核心可在测试宿主运行 | 未交付独立服务就宣称无需 DSH |

### 6.2 推荐仓库处置

最清晰的路线是建立新的**非 fork 仓库**承载新产品，旧仓库仅保留历史与转向说明。不要直接删除旧仓库重建，也不擅自清理用户发行物。是否保留完整 Git 历史由项目治理决定；即便重建干净历史，也应保存基线提交、变更来源和许可证清单。

如果选择平台提供的 fork 脱离途径，需要在实际执行时确认其条件及后果；仅执行 `git remote remove upstream` 不会修改 GitHub 的 fork 关系。该步骤不是本次文档阶段已经完成的操作。

### 6.3 独立发行验收

新仓库的 package/repository/bugs/homepage 指向自身；CI 只从固定可信依赖源构建；安装文档、更新检查、诊断上报、示例命令不回指原插件上游；不配置自动 merge/rebase 原插件；发布凭据由当前项目拥有。运行时第三方包仍允许正常依赖，但必须锁版本、扫描和记录来源。

现有 LICENSE 明确保留 NAMEWTA 与 sunny0826 的版权通知；保留原代码或其重要部分时，独立化不应删除该通知。新增代码和改动可单独记入版权及 NOTICE，第三方主题、图标、字体还要逐项检查，不能假设仓库代码许可证覆盖全部资产。[S16]

### 6.4 不兼容的具体定义

旧路由、旧工具名、旧组件导出、旧配置键、旧 RPC、旧存储版本均可被删除，不提供运行时兼容分支。新平台自己的未来版本仍需要正常的数据版本管理，这与不兼容旧项目不矛盾。

新安装使用新命名空间；保留旧目录作为只读备份或由用户自行清理，不擅自删除。已有 Herdr pane/工作区是外部服务中的活动资源，不是“旧格式垃圾”。卸载或首次启动不得批量终止这些资源。一次性导出/人工重建不等于维护双版本运行时。

## 7. 目标架构与依赖规则

### 7.1 模块化单体

```text
DSH 宿主                 开发/测试宿主                 后续独立宿主
   │                         │                            │
   └──────────── 宿主适配契约 HostBridge ───────────────────┘
                             │
                平台运行时 + 权限 + 配置 + 审计
                             │
                模块注册表 / 模块生命周期 / 贡献注册
                  │                          │
             Herdr 模块                  示例/未来模块
       ┌──────────┼──────────┐
     领域       应用服务     Web 页面
       │          │             │
    纯模型      端口接口      UI 包 + 查询客户端
                  │
           Herdr 协议/进程适配器
                  │
           外部 Herdr daemon
```

平台核心只定义身份、能力、命令、查询、事件、配置、日志和模块注册。Herdr 的 workspace、tab、pane、agent、terminal lease 由 Herdr 模块拥有。公共包不得变成把所有业务类型堆在一起的 `shared`。

### 7.2 可机器检查的依赖规则

| 层 | 可以依赖 | 禁止依赖 |
|---|---|---|
| platform-core | 平台 contracts、标准库 | React、DSH、Herdr、业务模块 |
| module-sdk | 平台 contracts、必要类型 | 任何具体模块、具体宿主 |
| ui | React、选定原语、token | Node、Herdr、DSH SDK、业务网络接口 |
| Herdr domain | 自身 domain 类型 | React、Node IO、DSH、数据库 |
| Herdr application | domain、端口、模块 contracts | 宿主私有 API、DOM |
| Herdr infrastructure | application 端口、Herdr 协议、Node IO | Web 组件 |
| Herdr web | 自身公开 contracts、UI、SDK query/action 接口 | host 文件、Socket、child_process |
| DSH adapter | DSH 公开 SDK、平台端口 | Herdr 内部领域实现 |
| 组合入口 | 上述公开导出 | 从其他包深层路径绕过 exports |

通过 ESLint import 规则、TypeScript project references、package exports 和依赖图检查落实，不依靠文档约定。模块间调用只走公开服务/事件，并声明依赖；不得跨目录直读对方数据库或 store。

### 7.3 数据与权威

Herdr 运行时事实由 Herdr 提供，Host 应用服务将其归一为本产品读模型，Web 缓存负责展示。用户偏好、审计、模块配置属于工作台。现有 DSH session observable 仅通过 adapter 映射，不允许一份状态同时被 DSH store、Query cache 和自建全局 store 分别当作权威写入。

## 9. 技术栈选型与取舍

| 层面 | 推荐 | 原因与限制 |
|---|---|---|
| 语言 | TypeScript strict，开启精确可选属性等规则并逐项验证 | 将非法状态提前暴露；不以 `as never` 穿透边界 |
| 前端框架 | React 19，与宿主 React/React DOM 对齐 | 现有项目已使用；嵌入入口必须避免双 React 实例 |
| UI | shadcn/ui + Base UI，仅一个原语基座 | 可定制工作台风格；组件源码由项目负责维护升级 |
| 样式 | Tailwind CSS 4 + 语义 CSS variables + 模块作用域 | 嵌入模式不向宿主注入全局 Preflight |
| 构建 | Vite 用于独立开发壳；tsdown 用于宿主/库产物 | 不强迫 DSH 加载未经验证的 Vite bundle；正式 Web 打包遵守宿主模块要求 |
| 服务端状态 | TanStack Query | 统一缓存键、失效、重取与 pending/error；重试策略必须按操作定义 |
| 本地 UI 状态 | React 局部状态；确有跨页面需求再使用轻量 store | 不用 Zustand/Redux 重复保存服务端实体全集 |
| 路由 | 受控 React 路由层，嵌入/独立不同 adapter | 不接管宿主 history；深链能力以已验证公开接口为准 |
| 协议 | Zod schema + 显式 action/query 定义 + 生成客户端 | 单源生成参数个数与错误结构，修复契约漂移根因 |
| 终端 | xterm.js，按需加载 | 后端独立会话管理、背压和控制权；不每卡一实例 |
| 运行时 | Node 24 固定验证版本，pnpm 工作区与锁文件 | 不因竞品使用 Bun 就同时引入第二服务端运行时 |
| 存储 | 首发宿主存储端口 + 原子配置/元数据审计；可选 SQLite 适配 | 不为单用户本地插件默认引入远程数据库/Redis |
| 测试 | 单元测试、Testing Library、Playwright、Storybook 与契约测试 | UI 故事不是 E2E；mock 通过不是实机通过 |

**UI 备选判断。** Ant Design 适合大量标准化后台表单与表格，本项目的终端、待处理侧栏、主从工作区和定制视觉占比较高，故本次优先 shadcn/ui。选择它不是声称比 Ant Design“更主流”，而是更贴近定制工作台的约束。若后续团队选择 Ant Design，应整体替换 UI 基座，不允许各模块各选一套。[T02] [T03]

截至调研可见的 shadcn 文档，Base UI 为默认基座，Radix 仍受支持，React Aria 已作为另一个可选基座。本项目显式选 Base UI，不把三套实现混在同一设计系统。[T02]

TanStack Query 的默认 stale/refocus/retry 行为不应原样套到终端控制。读取可以有界重试，写入和按键不能因查询库默认行为自动重发。Tailwind Preflight 会修改全局元素默认样式，嵌入式产品必须单独处理作用域；class 前缀不是完整的样式隔离措施。[T04] [T05]

具体补丁版本在实现 M0 冻结并记录锁文件及安全审计，不把搜索缓存中的版本写成“2026-10-21 全球最新版”。

## 10. 功能模块 SDK 与运行生命周期

### 10.1 模块不是页面目录

一个合格模块应能声明自己的业务契约、页面、导航、动作、设置、后台任务和能力需求；能被启用、停用、隔离故障并清理贡献。它不必独立部署，但不能依赖平台手工改导航才能被发现。

首发模块是仓库内经过审查、随发行包构建的第一方模块。Web 懒加载只是减小初始加载和延迟初始化，不是安全沙箱。Host 模块同进程运行，拥有相同进程权限；能力声明约束受控 API 的使用，不阻止恶意同进程代码绕过 SDK。第三方代码必须另设进程/沙箱、签名、来源与权限审核，再讨论动态安装。

### 10.2 Manifest 示例

以下为设计接口，不是已发布 SDK，也不是 Herdr 自身的 `herdr-plugin.toml`：

```ts
export const manifest = {
  id: 'herdr',
  version: '1.0.0',
  platformApi: 1,
  titleKey: 'modules.herdr.title',
  dependencies: [],
  requestedCapabilities: [
    'herdr.read',
    'herdr.workspace.manage',
    'herdr.terminal.observe',
    'herdr.terminal.control',
  ],
  contributions: {
    routes: ['herdr.overview', 'herdr.workspaces', 'herdr.attention'],
    navigation: ['herdr.primary'],
    widgets: ['herdr.attention-summary'],
    settings: ['herdr.connection'],
    actions: ['herdr.workspace.create', 'herdr.pane.close'],
  },
  entries: {
    host: './host',
    web: './web',
  },
} as const;
```

Manifest 仅含可序列化元数据；真实组件和处理函数由受控代码入口注册。入口解析以构建时允许列表为准，不把 manifest 中的任意 URL 当成可执行代码地址。

### 10.3 生命周期

```text
discovered → validated → registered → starting → active
                                  ↘ failed
active → draining → stopped → disposed
```

校验重复 ID、API 主版本、依赖环和权限声明；同一批贡献注册失败时回滚已注册的导航、动作、路由和任务。模块启动失败只影响该模块，平台仍可进入诊断。停用先阻止新操作，再等待受控任务取消或结束，释放 Web 订阅、计时器和本产品启动的桥接进程，最后移除 UI 贡献。

**停用 Herdr 模块不等于停止 Herdr 服务，不等于关闭用户 Agent，也不等于删除工作区。** 有未提交输入或控制会话时先警示；清理失败显示 `draining/failed` 与可诊断原因，不能界面假装已完全卸载。

### 10.4 扩展点治理

| 扩展点 | 模块提供 | 平台负责 |
|---|---|---|
| 页面/导航 | route ID、标题、图标、加载函数 | 唯一性、权限过滤、排序、错误边界 |
| 首页摘要 | 有界的数据摘要、跳转目标 | 布局、空态、加载预算、刷新调度 |
| 命令 | schema、能力、作用范围、确认规则、处理函数 | 发现、授权、审计、执行状态 |
| 设置 | schema、默认值、敏感字段声明、校验 | 表单外壳、脏状态、原子提交、存储命名空间 |
| 后台任务 | 周期/触发器、取消方法、资源预算 | 去重、取消、错误记录、停用清理 |
| 事件 | 有版本的领域事件 | 订阅生命周期、背压、日志元数据 |
| 通知 | 严重级别、去重键、资源引用 | 收件箱、静默、隐私、渠道策略 |

不允许模块直接修改平台路由数组、全局 CSS、另一个模块 store 或任意宿主 DOM。新增模块必须通过架构测试证明可在未安装 Herdr 的情况下独立加载。

### 10.5 第二模块验收

用一个最小 `example-notes` 模块贡献页面、设置项、命令和首页摘要。添加它只修改模块清单/组合配置，不改平台壳和 Herdr。停用后路由、计时器和订阅全部消失；使其页面抛错时 Herdr 不白屏。正式包默认排除它，避免用无实际价值的示例功能污染产品。

## 11. 领域模型、状态语义与数据真实性

### 11.1 资源模型

```text
ConnectionProfile ── HostEndpoint ── HerdrSessionInstance
                                         └─ Workspace
                                              └─ Tab
                                                   └─ Pane
                                                        └─ AgentOccupant / AgentRun

DSHConversation ── SessionBinding ── Workspace
BrowserClient ── TerminalLease ── PaneInstance
UserPreference / AuditRecord / AttentionItem 为工作台自有实体
```

连接配置是持久对象；Herdr 服务实例具有 epoch；pane 的公开 ID 是地址，不一定是永久身份。重启、移动或 occupant 替换后，不能仅凭同一个 `w1:p1` 继续执行旧动作。若服务提供稳定 terminal ID，则纳入身份；若没有，绑定当前实例、创建/观察代数并在危险写入前重新确认。

### 11.2 建议资源引用

```ts
type ResourceRef = Readonly<{
  connectionId: string;
  herdrSessionId: string;
  serverEpoch: string;
  resourceKind: 'workspace' | 'tab' | 'pane';
  resourceId: string;
  terminalId?: string;
  occupantRef?: string;
}>;

type SnapshotMeta = Readonly<{
  snapshotRevision: number;   // 本工作台归一化投影版本，不冒充 Herdr 全局事件序号
  capturedAt: string;
  receivedAt: string;
  freshness: 'fresh' | 'stale' | 'unknown';
  coverage: 'complete' | 'partial';
  unavailableCollectors: string[];
}>;
```

跨主机实体主键必须包含 connection 和 session。浏览器 Query key 使用 `[moduleId, connectionId, sessionId, epoch, resource, filters]`；切换连接时取消旧请求并丢弃旧 generation 的响应，避免慢返回覆盖新页面。

### 11.3 不混为一个颜色的五组状态

| 维度 | 典型值 | 展示与行为 |
|---|---|---|
| 连接状态 | connecting / healthy / degraded / disconnected / unsupported | 影响读取可信度和动作可用性，不篡改 Agent 原状态 |
| 原始 Agent 状态 | working / blocked / idle / done / unknown | 原样保存来源与采样时间，再生成一致展示 |
| 待处理原因 | question / approval / operation-error / unread-completion / none | 只有可靠证据才能细分 approval；否则显示“需要查看” |
| 控制权 | observer / requesting / controller / conflict / revoked | 服务端判定；UI 不以本地布尔值充当权限 |
| 资源归属 | external / owned / explicitly-adopted | 自动清理只允许明确归属的资源 |

Herdr 当前文档将 `done` 描述为 idle 且尚未被查看，而不是“任务已成功且退出码为 0”。工作台应保留该语义，不用 done 推导构建成功率；工作台用户自己的“已读”也不应未经定义就改写服务端所有客户端的 seen 状态。[H01]

### 11.4 指标口径

| 指标 | 口径 | 禁止的误导 |
|---|---|---|
| 工作区数 | 当前明确选定连接范围内、成功采集的 workspace 数 | 部分连接失败时仍称“全部工作区” |
| 工作中 | 原始有效状态 working 的 Agent 数 | 把无状态 pane 算成工作中 |
| 待介入 | 有效 AttentionItem 去重后的数量 | 把一个资源的多个重复通知重复计数 |
| 完成未读 | 当前实例下未读完成提示 | 当成任务成功数或生产力得分 |
| CPU/RSS | 标注对象、采样时间、来源和单位 | 将 Node 宿主进程误标为整个主机或全部 Agent |
| 最近更新 | 本次成功权威采样时间与延迟 | 用浏览器页面刷新时间冒充服务采样时间 |
| 历史趋势 | 从实际持久或有界采样中计算，缺口断开 | 插值成“没有发生故障”，或无数据画平线 0 |

现有 dashboard DTO 已有过程采样和 partial/stale 相关字段，但未证明具备完整历史时间序列；历史曲线与每 Agent 进程树归属应作为新增采集能力，而不是换 UI 后凭空出现。[S15] [R13]

### 11.5 会话与所有权

DSH 对话与 Herdr 工作区绑定必须有显式记录，包含创建方、连接、服务实例、工作区、创建时间和策略。不能用 `label.startsWith('dsh:')` 或 Agent 名称推断删除权限。用户在 Herdr TUI 中改名，不应使资源失去身份；绑定不存在时 fail closed，不能退回“当前聚焦工作区”执行命令。

## 12. Herdr 接入、实时一致性与终端传输

### 12.1 三层能力区分

DSH 插件槽位是宿主组合机制；工作台模块是本项目的扩展机制；Herdr 插件 manifest 是外部 Herdr 的功能机制。这三者不能共享一个模糊的 `plugin` 类型，更不能认为安装一个工作台模块就获得了 Herdr 原生 UI 扩展能力。[H02] [H03]

Herdr 适配器应记录 binary 路径、版本、socket/pipe 可达性、server 实例和支持方法。安装版本与正在运行的服务版本可能不同。公开文档、网页缓存与本机二进制能力也可能不同，因此以冻结支持基线及实机 schema/探测为准，而不是把文档中的每个方法直接显示为可用。[H01]

### 12.2 支持基线与“无需兼容”

重构首发选定一套 DSH/Herdr 验证基线，不维护旧插件和多个历史宿主版本。能力检测用于安全地判断当前安装是否满足功能，不是保留旧代码兼容层。关键能力缺失则明确不支持；非关键能力缺失只禁用相应动作。

当前 CI 中出现的 Herdr 0.9.0/0.9.3、protocol 22 不能自动当作新产品永远唯一协议。文档还区分公共 JSON 能力与某些内部/直接终端操作的版本约束。M0 应保存实际 `api schema --json`、运行版本及终端探测输出，形成可复验的支持表。[S09] [H01]

### 12.3 元数据流：事件提示失效，权威读取修正

官方较新文档明确提醒：快照与事件没有共享序列边界；发生 `events_lost` 后需要重新订阅并读取快照，不能无条件把缓冲事件覆盖到快照上。旧缓存页面说明较简略，本设计采用保守的一致性策略，同时在冻结版本实测。[H01] [H04]

建议流程：建立订阅并等待确认；开始连续读取；用另一条请求通道读取快照；事件到达只标记相关读模型 dirty；同一范围最多一个 refresh 在飞；读取过程中又变脏，则完成后再读取一次。保留有界周期校验，恢复当前状态而不是伪造丢失历史。

```text
subscribe/ack
    ├─ events reader → dirty(scope)
    └─ snapshot request → normalize → publish(revision N)
                                 │
                   dirty during request? ── yes → refresh again
```

需要去抖但不能无限等待静默；连续高频事件下设置最大刷新延迟、单飞、合并范围和有界重试。断流、解析失败或事件丢失时显示 stale，不清空为 0。实例变更后清空旧 cursor 与控制 lease，重新核验资源。

本工作台可以为“Host → Web 的归一化投影”分配自己的 epoch/revision，以便前端检测跳号；这不能倒推外部 Herdr 的事件具有全局顺序。UI 收到缺口后请求完整投影，不擅自修补未知事件。

### 12.4 终端流：与普通查询彻底分离

终端采用独立数据通道，Host 负责桥接进程、会话和权限。只为可见且被打开的终端建立观察兴趣；总览不启动数百个终端实例。多个观察者能否共享底层流取决于模式、尺寸、权限和协议能力，不能为了节省进程而混用控制流。

每个流具有 session、generation、frame sequence、全帧基线和有界回放。首次 attach 或 cursor 失效时发送可用全帧及其后连续差量；找不到完整基线则重建，不能仅发送某个旧全帧后声称连续。既有管理器的这一约束是回归测试基线。[S10]

xterm 的 write 是异步缓冲操作，高产出可能使缓冲积压；本项目必须有帧/字节预算、消费确认、慢读者策略和背压。不能随意丢弃 ANSI 字节；无法维持连续时丢弃整段旧流并显式重建基线。[T08]

### 12.5 控制权与多窗口

观察默认只读。点击“取得控制权”后，由 Host 原子授予绑定身份、browser client 和具体 pane instance 的租约；同一 pane 同时最多一个受本产品管理的 controller。另一个窗口只可观察或发起显式接管，不得因为聚焦就抢占。

此租约只能约束本产品通道，不能声称阻止外部 TUI/CLI 的所有输入；如 Herdr 自身提供控制冲突能力，适配器也要处理。无法独占外部输入时在界面注明“其他客户端仍可能操作”。

断线后拒绝继续发键并显示投递状态不确定；恢复连接不重放旧按键。宽限期只保持可恢复会话资源，不赋予未鉴权新连接继续控制权。关闭浏览器页释放本产品 lease/桥接进程，不自动关闭底层 Agent。

### 12.6 尺寸、输入与边界情况

只有具有相应控制能力的客户端可改变实际共享终端尺寸；纯观察渲染尺寸尽可能与控制尺寸分离。Web 的 panel resize 不应无条件改变外部 TUI。中文输入法在 composition 完成前不发送中间按键，多行粘贴提示目标与风险；Enter、Ctrl+C、Tab、Esc 保持明确语义。复制有选区优先复制，不能在复制时向 shell 发 Ctrl+C。

暂停观察节省资源，但不是停止任务；停止 Agent 必须单独确认。流程中所有关闭与清理都有超时、真实进程退出证据和仍占用配额的异常状态，不能提前释放配额造成进程失控。

## 13. 仪表盘与关键页面详细设计

### 13.1 Herdr 总览：信息层级

第一层是范围与健康：当前连接、Herdr session、正常/部分失联、最后成功时间、重新连接/诊断入口。第二层是行动：需要查看、执行失败、完成未读。第三层才是工作区和 Agent 分布。CPU、RSS、协议、socket 路径、进程数进入运行概况或诊断，不占据首页中心。

```text
┌ 模块导航 ───┬────────────────────────────────────────────────────┐
│ 工作台      │ Herdr / 总览        本机 ▾  default ▾   搜索 ⌘K   │
│ Herdr       │ 已连接 · 更新于 2 秒前           [新建工作区]      │
│   总览      ├────────────────────────────────────────────────────┤
│   待处理 3  │ 待介入 2    工作中 8    完成未读 1    工作区 4    │
│   工作区    ├────────────────────────────────┬───────────────────┤
│   Agents    │ 需要你处理                     │ 近期活动          │
│   活动      │ 审批/问题 → 说明 → 查看上下文    │ 状态变化/操作结果 │
│   环境      │ 异常 → 原因 → 重试或诊断        │ 缺失区间明确标记  │
│             ├────────────────────────────────┴───────────────────┤
│ 设置        │ 工作区  [搜索] [状态] [归属] [列表/卡片]            │
│             │ 项目/路径    Agents状态   最近活动   打开 / 更多   │
└─────────────┴────────────────────────────────────────────────────┘
```

该图是信息结构示意，不是已完成视觉稿。首发不支持自由拖拽整个 dashboard 布局；先提供稳定默认布局、紧凑/舒适密度和列表/卡片两种视图，降低记忆与维护成本。

### 13.2 指标卡

卡片必须可点击进入对应过滤结果，并显示范围。未知与部分覆盖优先用“— / 部分数据”解释，数值不滚动、不夸张动画。颜色只加强语义，标签不可省略。加载时保留卡片高度，刷新时保留旧数据并标注刷新，避免整页闪空。

### 13.3 待处理中心

默认排序：已确认的严重操作失败、待人工审批/回复、其他 blocked、完成未读。用户置顶优先于普通排序；同一组使用稳定次序。鼠标正在操作或键盘已聚焦的行不突然移位，可提示“有新事项”再应用重排。

每条包含资源名称、完整目标范围、原因、来源可信度、产生时间、最新验证时间和一个主动作。不能只放红点或“blocked”。尚未解析出真实问题时显示“需要查看终端”，不臆造审批内容。

对完成未读提供标记已读；对仍在阻塞的事项提供暂时隐藏/稍后处理，但不得把隐藏当成问题已经解决。批量仅允许安全的已读标记，不提供“全部同意”或跨资源批量发键。

### 13.4 工作区列表

默认字段：名称、路径摘要、归属、tab/pane 数、Agent 状态摘要、最近活动、主要操作。完整路径放详情并支持复制；路径不因布局挤压完全消失。搜索匹配名称、标签、路径和 ID；状态过滤显示当前生效条件，可一键清除。

卡片视图适合少量工作区，表格适合大量资源；两种视图共用同一数据模型和操作组件，不各写一份动作逻辑。支持列显示偏好、稳定排序、键盘进入详情。多选默认只对当前过滤的可见结果生效，“选择全部结果”必须显式说明数量和范围。

### 13.5 工作区详情与终端

```text
工作区 / api-service       本机 · default     [重命名] [更多]
路径与归属 · 最新数据时间
┌ tabs / panes ──────┬──────────────────────────────┬─────────────────┐
│ backend  工作中    │ Terminal | 概况 | 事件        │ 选中 pane 信息  │
│ tests    需查看    │ 只读观察 · 其他窗口控制中     │ Agent / 路径    │
│ shell    空闲      │                              │ 归属 / 控制状态 │
│                   │           终端               │ 最近操作        │
│ [新增 pane]       │                              │ [诊断]          │
└───────────────────┴──────────────────────────────┴─────────────────┘
                              [取得控制权] / [释放控制权]
```

主内容区保持终端稳定，侧边元信息更新不重建 xterm。详情侧栏可折叠；用户改动列宽后以工作区/用户偏好保存。全屏终端保留可退出按钮、目标、连接和控制状态。切换 pane 前保留独立草稿，旧草稿不得污染新目标。

### 13.6 Agents 页面

按 Agent 类型、运行状态、工作区、归属过滤；列表显示 Agent 名、任务摘要来源、所在 pane、状态时间、待处理原因。任务摘要来自可靠元数据或明确记录，不用未经标注的模型推测补齐。可以启动新 Agent、进入现有 pane、查看生命周期记录；“Agent 完成”不自动关闭工作区。

启动表单选择已探测到的可执行 Agent、目标目录/工作区、参数模板和必要环境项。服务端校验路径、资源归属和 capability；不把用户字符串直接拼成 shell 命令。高级任意 shell 启动若启用，视为独立高风险能力，不伪装成安全参数模板。

### 13.7 环境与连接页面

按“运行环境 → CLI → 服务 → 协议/能力 → 终端验证”分步骤显示。明确探测发生在 DSH Host 机器，而不是浏览器机器。安装缺失、PATH 不可用、服务未启动、权限不足、协议不满足应是不同错误。

提供可复制的人工安装说明、可执行路径设置、重新检测以及显式启动服务；不在打开页面时 curl|bash，不自动 sudo，不自动升级/停止现有 Herdr。涉及现有服务重启时展示受影响工作区并要求确认；首发可只提供说明而不提供重启执行。

### 13.8 活动与诊断

“活动”是资源变化，“审计”是由谁发起了什么动作，两者可关联但不可互相替代。列表支持资源、时间、操作结果筛选，并说明保留范围。丢失外部事件时插入“连接中断/历史不完整”段，不虚构补齐。

诊断展示 build、协议、能力、collector、请求延迟、终端配额和最近错误。导出前预览字段并默认去除用户名、绝对路径、token、输入正文和终端内容。不要因为是诊断包就绕过用户的数据边界。

### 13.9 手机与窄容器

布局按插件可用容器宽度适配，而不是只按整块显示器宽度。窄屏使用单列待处理和工作区列表；详情进入独立视图，次要信息进入 drawer。主要触控区目标 44×44 CSS px；底部输入遵循 safe-area 和软键盘变化。P0 提供可用的窄屏管理与安全终端，P1 再增加 PWA、推送、设备配对等生产能力。

## 14. 全局设计系统规范

### 14.1 视觉方向

定位是专业、安静、信息密度可调的开发工作台。使用中性背景、轻量分隔和单一主色；状态标签承担彩色信息，终端保留自己的 ANSI 调色。不要大面积渐变、彩虹卡片、发光边框、连续闪烁或把每个状态都做成成功绿色。

建议起始色板如下，属于本项目设计输入，不代表已经通过全部组合对比度测试：

| 语义 token | 浅色建议 | 深色建议 | 使用范围 |
|---|---|---|---|
| `surface.canvas` | `#F6F7F9` | `#111318` | 页面底层 |
| `surface.panel` | `#FFFFFF` | `#191D25` | 内容容器 |
| `surface.raised` | `#FFFFFF` | `#232936` | 浮层、选中层 |
| `text.primary` | `#172033` | `#EDF1F7` | 主要内容 |
| `text.secondary` | `#526078` | `#AFBBD0` | 次要但可读信息 |
| `border.subtle` | `#DCE2EB` | `#353E50` | 低强调分隔，不用于唯一状态提示 |
| `action.primary` | `#2457D6` | `#88AEFF` | 主操作、焦点、选中 |
| `status.working` | `#1D5FA8` | `#8BC1FF` | 正在执行 |
| `status.attention` | `#946000` | `#F2C66D` | 需要人介入 |
| `status.error` | `#B42332` | `#FF9BA7` | 明确失败/危险 |
| `status.complete` | `#246847` | `#91D7AE` | 完成提示，不代表任务成功 |

所有实际文字/背景、禁用态、图标与焦点组合必须自动检测并人工验收。不能以“组件库无障碍”替代项目自身验证。

### 14.2 尺寸、密度与动效

基础间距 4px，常用 8/12/16/24/32；正文建议 14px、行高 1.5，页面标题 22—24px，二级标题 16—18px。元信息通常不小于 12px；终端字号独立设置，不受表格紧凑模式挤压。

普通控件高度 36px、舒适模式 40px；表格行高初始 40/48px 两档。内容卡圆角 10—12px，输入 6—8px；同一层级不混用五六种圆角。悬浮反馈 120—180ms，布局切换不强制大幅动画；尊重减少动态效果设置。

断点以容器为依据：小于 720px 单列，720—1199px 主内容+可折叠导航，1200px 以上可展示主从+详情。此为起始规范，需在 DSH 实际可用空间校准，不能仅在独立 demo 中验收。

### 14.3 组件目录与治理

基础组件包括 Button、IconButton、Input、Select、Combobox、Dialog、Popover、Tabs、Menu、Tooltip、Toast、Skeleton、EmptyState。组合组件包括 PageHeader、ScopeSelector、HealthBanner、MetricCard、FilterBar、DataTable、ResourceBadge、StatusBadge、ActionMenu、ConfirmActionDialog、ErrorPanel、SplitView、TerminalToolbar。

业务模块只从 `@workbench/ui` 获取通用组件；禁止直接再次安装另一个 Dialog 或 Table 库。业务专用组件可保留在模块内部，但使用相同 token、状态规则和交互规范。修改公共组件需要 stories、亮暗截图、键盘测试和变更记录。

### 14.4 宿主样式隔离

所有工作台 CSS variables 放在明确根节点，并使用工作台前缀；只在根范围内做必要 reset。Tailwind 禁用全局 Preflight，utilities 带前缀，仍需检查继承字体、`button`、`svg`、`box-sizing` 等影响。Dialog/Popover 的 portal container 指向工作台管理的浮层根，防止离开主题作用域后颜色或 z-index 失控。[T05]

不要为了覆盖宿主 CSS 到处增加 `!important`。Shadow DOM 仅在确有冲突且完成焦点、portal、xterm 和宿主交互验证后考虑，不作为首发默认捷径。

### 14.5 无障碍与交互一致性

普通文本对比度目标至少 4.5:1，大文本与必要非文本控件对比按 WCAG 对应规则检查；必须有可见焦点、不被浮层完全遮挡、状态不只依靠颜色。WCAG 2.2 AA 的目标尺寸规则含 24px 及间距等例外；本产品手机端采用更宽松的 44px 触控目标作为设计目标，而不是混称 44px 为所有 AA 控件的硬性标准。[T09]

确认弹窗初始焦点优先取消，关闭后返回触发按钮；异步执行不能把焦点丢到页面根部。列表键盘导航与终端键盘输入必须有明确边界，命令面板快捷键不得吞掉用户正在输入的 shell 控制键。Toast 不是唯一错误记录；长文本错误提供可复制详情与 requestId。

### 14.6 通用状态规范

| 状态 | 界面要求 |
|---|---|
| 初次加载 | 结构化 skeleton，不能显示假统计数字 |
| 后台刷新 | 保持旧内容，轻量刷新指示，不闪整屏 |
| 真正为空 | 解释范围，提供明确创建或修改筛选动作 |
| 搜索无结果 | 保留搜索条件与清除入口，不建议重新安装 |
| 部分失败 | 保留可用部分，标明缺失 collector/连接 |
| 断线/过期 | 显示最后成功时间，禁用依赖最新状态的危险写入 |
| 不支持 | 显示缺少能力和解决路径，不伪装成空数据 |
| 无权限 | 显示拒绝原因，不泄露资源细节或只隐藏按钮 |
| 操作结果不确定 | 提示核验实际状态，不重复发送可能已执行的动作 |

## 15. 关键功能流程与业务验收

### 15.1 首次进入

先解析模块清单，再取得宿主身份与能力，加载全局外观，最后执行 Herdr 环境检测。无 Herdr 时显示引导而非报错白屏；无访问权限时不发起敏感探测。用户配置路径后执行受控检测并展示结果，成功后才进入实际总览。

验收：缺 binary、服务停止、socket 权限拒绝、能力不足、正常连接五种 fixture 分别呈现不同说明；刷新页面不会自动执行安装或启动命令。

### 15.2 创建工作区

输入名称、绝对工作目录和可选初始 Agent；服务端验证路径与能力；以 requestId 记录创建意图；成功后权威读取并进入新资源；部分成功时显示已经创建了什么。不得因 Agent 启动失败再次创建整个工作区，重试只针对失败步骤。

验收：双击提交不产生两个工作区；响应丢失后不能盲目重试；同名工作区可存在时不把名称当幂等键；错误字段定位到具体输入。

### 15.3 从待处理进入资源

点击事项先验证连接与资源实例，再打开具体 pane；已失效事项显示“资源已结束/已替换”，保留可查看审计。结构化问题无法确认时只展示终端，不发送假设性的 yes/no。

验收：事项来自 A 主机时，在切换到 B 主机后仍不能误操作 B 的同名 pane；返回列表时保留筛选和滚动位置。

### 15.4 取得/释放控制权

只读模式下可选择、复制和滚动，不发送任何输入；点击取得控制后后端原子授权，界面收到实际 lease 才启用输入；冲突时显示观察与显式接管选项。接管再次确认对象，旧 controller 收到撤销并立即禁输。

验收：两个窗口同时申请只有一个成功；旧 token 重放被拒；页面关闭只释放本产品控制，不停止底层 Agent；外部控制冲突单独显示。

### 15.5 关闭资源

关闭 pane、关闭工作区、停止桥接观察与停止 Herdr 服务是不同动作，使用不同文案和权限。关闭工作区前显示 tab/pane/Agent 数及归属，使用最新 revision/epoch 再校验。若期间对象变化，要求刷新确认，不对新 occupant 使用旧确认。

验收：取消不改变数据；权限失败不伪装为成功；外部资源不会随 DSH 对话关闭而自动删除；批量关闭部分成功时逐项返回结果。

### 15.6 断线恢复

断线后保留最后可信视图、时间与错误原因，禁用控制输入；有界退避重连，订阅确认后权威刷新。服务实例改变时废弃旧会话与控制 token；新对象需要重新授权。历史事件缺口显示为缺口，不能承诺离线期间无遗漏。

验收：数据不会归零又跳回；恢复不重复创建工作区、不重放输入、不恢复未经确认的控制；失败的单个 collector 不摧毁整个页面。

### 15.7 设置保存

用户编辑时区分本地未保存值、持久值与运行值。保存经过 schema 和能力校验后原子提交；需要重新连接/重启的项明确提示。保存失败保留输入，显示字段与原因；不在 every keystroke 修改运行服务。

### 15.8 模块停用

先展示正在运行的本产品任务和终端 lease，再进入 draining；阻止新请求、取消订阅、释放桥接资源；结束后移除贡献。不能因清理超时把整个工作台卡死，也不能提前显示完全已停用。

### 15.9 结构化聊天与审批的后续能力

聊天视图属于 P1；必须由 Agent 适配器取得可证明属于当前 occupant 的 transcript。找不到映射时明确“不支持/无法定位”，保留终端兜底，不用目录最新日志猜测。审批卡携带 prompt identity/revision/context hash，并在提交前验证仍是同一问题；不支持条件执行的底层接口上仍存在竞态，因此不能宣传事务级审批保证，必要时只开放用户手动终端处理。

聊天不持有另一套独立任务状态，不绕过控制权限；“发送文本”和“发送文本并 Enter”是不同意图。结果不确定时不能自动二次发送。不得自动显示或持久化不必要的私密推理、token 或凭据。

### 15.10 多主机后续能力

P1 增加多主机时，沿用首发复合 ID 与独立连接状态。每个连接有认证、已验证主机身份、超时和配额；一台断线不阻塞其他连接。文件、端口代理和 SSH 凭据不是只加一个 URL 字段，应单独完成路径隔离、来源约束、撤销和审计设计后上线。

## 17. 查询、动作与错误契约

### 17.1 统一请求封装

新接口统一使用一个 request envelope，即便业务参数为空也传递显式空对象；不继续维护“某些零参数、某些一个参数、生成器另有例外表”的隐式约定。Host 的 DSH 描述符必须由同一协议定义生成，真实打包产物验证 arity。[S01]

```ts
type RequestEnvelope<T> = Readonly<{
  apiVersion: 1;
  requestId: string;
  target?: ResourceRef;
  input: T;
}>;

type Result<T> =
  | { ok: true; data: T; requestId: string }
  | {
      ok: false;
      error: {
        code: string;
        messageKey: string;
        retryable: boolean;
        outcome: 'not-executed' | 'executed' | 'unknown';
        details?: Record<string, unknown>;
      };
      requestId: string;
    };
```

这是新工作台应用协议，不是 Herdr 原生 socket 包格式。请求处理链：校验 schema → 解析身份/能力 → 校验目标范围与实例 → 验证前置条件 → 执行用例 → 记录操作结果 → 刷新读模型。`details` 只包含脱敏的允许字段。

### 17.2 首发接口目录

| 类型 | 应用接口（拟定） | 规则 |
|---|---|---|
| 查询 | `platform.modules.list`、`platform.context.get` | 权限过滤后返回贡献与运行态 |
| 查询 | `herdr.environment.inspect`、`herdr.capabilities.get` | 探测和执行分离，无隐式安装 |
| 查询 | `herdr.overview.get`、`herdr.workspaces.list/get` | 含 scope、freshness、coverage |
| 查询 | `herdr.agents.list`、`herdr.panes.get`、`herdr.attention.list` | 不将缺失对象当作空字符串 |
| 动作 | `herdr.workspace.create/rename/close` | close 带最新确认与资源范围 |
| 动作 | `herdr.tab.create/rename/close`、`herdr.pane.split/rename/close` | 仅对已支持能力开放 |
| 动作 | `herdr.agent.start`、`herdr.binding.create/release` | 显式所有权；部分成功可诊断 |
| 终端 | `herdr.terminal.observe/acquire/release/takeover` | 受控 lease，实例与身份绑定 |
| 终端流 | `attach`、`frame`、`ack`、`input`、`resize`、`closed` | 独立传输协议，不经过普通查询缓存 |
| 动作 | `platform.module.enable/disable`、`platform.settings.save` | 系统级能力；原子更新及生命周期 |
| 查询/导出 | `platform.audit.list`、`platform.diagnostics.export` | 查询有权限；导出可预览及脱敏 |

以上是应用层服务名称，不承诺 Herdr 有同名原生方法。Herdr adapter 将其映射到冻结版本支持的公开 API，缺失能力返回明确错误，不通过私有入口补洞。

### 17.3 AI 工具入口

当前 README 描述 19 个 `herdr_*` 工具；新项目不需要保留其名字或参数形态，但应明确用例覆盖，不能仅重做 Web 页面就遗漏 Agent 调用路径。[S06]

新工具由模块贡献，并复用同一 application use case、授权、资源解析与审计。工具输入必须给出明确 scope，写入不能省略目标后落到“当前聚焦 pane”。工具结果区分成功、失败、部分完成与结果不确定；不返回虚假“已启动”文本。高风险关闭/接管按宿主可验证的用户授权机制处理，不由模型自己声称已经确认。

### 17.4 并发、幂等与投递不确定

对工作区创建等业务动作，在 Host 保存有界 requestId 结果并拒绝同 ID 不同载荷；但外部 Herdr 若不支持原生幂等/事务，Host 在崩溃或回应丢失时仍可能无法确定执行状态。此时返回 `outcome: unknown`，通过可靠归属元数据核验，不能许诺端到端 exactly-once。

改名与关闭可带 expectedRevision/epoch，服务端读取最新状态再判断。该检查若无法和外部写入原子完成，只能减少竞态，不能宣称完全消除 TOCTOU；危险操作需优先使用外部原子能力或保守拒绝。

原始终端按键不走通用幂等重试。`inputSequence` 可以用于本产品通道拒绝重复已接收包，但不能证明 shell 只执行一次，更不能断网后自动重放不确定输入。

### 17.5 错误码与用户动作

| 错误码 | 意义 | 展示与恢复 | 自动重试 |
|---|---|---|---|
| `ENV_BINARY_MISSING` | 可执行不存在 | 指向路径设置/人工安装 | 否 |
| `SERVER_UNREACHABLE` | 服务或 socket 不可达 | 最后成功时间、重连、诊断 | 有界读取重试 |
| `CAPABILITY_UNSUPPORTED` | 所需能力不存在 | 禁用动作，说明支持要求 | 否 |
| `IDENTITY_REQUIRED` | 宿主身份不可用 | 重新认证/宿主诊断 | 否 |
| `PERMISSION_DENIED` | 权限不足 | 说明能力缺失，不泄露敏感详情 | 否 |
| `RESOURCE_GONE` | 对象已结束 | 返回列表并刷新 | 否 |
| `RESOURCE_REPLACED` | 同地址已经是新对象 | 丢弃旧动作，要求重新选择 | 否 |
| `LEASE_CONFLICT` | 其他 controller 占用 | 只读/明确接管 | 否 |
| `LEASE_EXPIRED` | 控制权失效 | 立即禁输，重新申请 | 否 |
| `STREAM_RESYNC_REQUIRED` | 缺基线或序列不连续 | 重新 attach/取得全帧 | 有界 |
| `QUOTA_EXCEEDED` | 超过进程或观察预算 | 关闭不用的观察，显示用量 | 否 |
| `OPERATION_OUTCOME_UNKNOWN` | 可能已经执行 | 先查验真实状态 | 否 |
| `COLLECTOR_PARTIAL_FAILURE` | 部分采集失败 | 保留有效内容和缺失标记 | 仅失败读取 |
| `MODULE_DRAIN_FAILED` | 资源尚未完全释放 | 保留占用与诊断信息 | 受控清理 |

## 18. 配置、存储与审计

### 18.1 数据所有权与持久化

| 数据 | 所有者 | 建议存储 | 默认保留 |
|---|---|---|---|
| 主题、密度、列表偏好 | 平台/用户 | 宿主设置或新命名空间 | 用户清除前 |
| 模块启用与非敏感配置 | 平台 | 受 schema 管理的宿主存储 | 持久 |
| DSH 会话绑定、资源归属 | Herdr 模块 | Host 持久存储，原子写入 | 资源生命周期+可配置审计期 |
| 连接凭据、认证 token | 宿主/连接适配器 | 宿主凭据机制或受限服务端存储 | 可撤销，最短必要期限 |
| 活跃控制 lease | Herdr 运行时 | Host 内存 | 断线、过期或释放即失效 |
| 元数据快照 | Herdr 运行时 | 有界内存缓存 | 当前实例 |
| 终端帧/回放 | 终端运行时 | 有界内存 | 当前会话与宽限期 |
| 操作审计元数据 | 平台 | 本地持久日志/存储适配器 | 建议初始 7 天，限额清理 |
| 历史性能采样 | 后续观测能力 | 可选 SQLite 等专门存储 | P1 提供可配置 7/30 天 |
| 对话与原始终端正文 | 外部 Agent/Herdr | 首发不另做永久副本 | 不默认持久化 |

审计建议记录时间、actor 标识、module、action、目标脱敏引用、requestId、结果、耗时和受限原因码。输入内容只记长度/类型等必要元信息，且无需无意义地保存内容哈希；哈希也可能暴露低熵秘密。默认不记录密码、按键流、完整命令正文或 transcript。

### 18.2 配置分层

平台默认值 → 模块默认值 → 管理员配置 → 用户界面偏好，优先级必须可解释。安全权限、可执行路径与服务端网络配置不能被浏览器偏好覆盖。每个设置声明是否敏感、是否需要重连、是否需要重启、是否可用户覆盖。

新配置命名空间与原插件分离。未来新产品自己的 schema 版本升级用显式迁移并保持备份；遇到高于支持版本的配置拒绝写入，不自动降级覆盖。

### 18.3 首发存储实现的边界

优先复用已验证的宿主持久化端口；没有满足原子写/权限/容量需求的接口时，由 adapter 提供受限本地文件实现。追加审计须有轮转、文件权限和崩溃尾部恢复；“用了 JSON 文件”不能等于没有一致性设计。SQLite 可作为以后查询历史的实现，不让其类型渗透到 domain。

## 19. 安全与权限设计

### 19.1 威胁模型

需要防范恶意网页借本地端口发请求、被盗浏览器会话、越权读取另一个连接、旧 lease 重放、资源 ID 复用、终端输出注入、错误命令目标、无限帧/事件导致资源耗尽，以及模块/依赖供应链风险。普通可信 first-party 模块同进程运行不构成安全隔离，这一点必须在开发文档中说明。

可写终端本质上能够以运行用户权限执行指令；路径 allowlist 或简单命令黑名单不能把任意 shell 变成安全沙箱。Collie 的安全文档明确承认此权限范围，值得借鉴的是风险透明，而不是照抄其全部权限策略。[R02]

### 19.2 能力矩阵

| 能力 | 只读身份 | 操作身份 | 管理身份 |
|---|---|---|---|
| 基础健康与获授权元数据 | 允许 | 允许 | 允许 |
| 终端内容观察 | 单独授权，不自动等同基础只读 | 按资源授权 | 按资源授权 |
| 工作区创建/重命名 | 禁止 | 允许范围内 | 允许范围内 |
| 终端输入 | 禁止 | capability + 有效 lease | 同样需要 lease |
| 显式接管 | 禁止 | 需额外能力与确认 | 同样记录审计 |
| 关闭外部资源 | 禁止 | 需额外授权 | 仍需明确目标与确认 |
| 停止服务/改变网络/凭据 | 禁止 | 默认禁止 | 单独能力与风险确认 |
| 模块启停/诊断导出 | 默认禁止敏感部分 | 按范围 | 允许且审计 |

不能把“管理员”解释为免除确认、目标校验或审计。前端是否显示按钮只影响可发现性；服务端必须重新校验每次动作和每条终端输入消息。

### 19.3 传输与身份

DSH 模式复用经过验证的宿主身份/请求边界，不另开免认证旁路端口。必须验证该宿主版本实际提供的身份、Origin 和权限机制，缺失关键条件时阻止远程写入。独立服务未来使用安全会话、明确来源允许列表、CSRF 防护和会话撤销；WebSocket 握手通过后仍需消息级鉴权与会话过期处理。[T07]

远程连接使用加密传输。浏览器不直接连接本机 Unix socket，不暴露 SSH 私钥，不在 URL query 放长期 token。只有一次性、有时效且可撤销的配对入口可考虑二维码；扫描成功也不应自动赋予所有主机控制权。

### 19.4 输出、链接、剪贴板与文件

终端输出与 Agent 文本视为不可信。Markdown/HTML 渲染必须清洗；链接限定安全协议，并在打开外部地址时隔离 opener。禁用不必要的终端剪贴板控制功能；读取/写入系统剪贴板需要清晰用户动作。xterm 的存在不会自动解决网页 XSS 或远程 shell 暴露问题。[T06]

首发不提供任意文件浏览与端口代理。后续文件模块需要 realpath、符号链接、文件大小、内容类型、下载与上传限制；简单 `startsWith(path)` 不能作为路径授权。终端用户仍可能经 shell 访问其他文件，应明确这是不同权限边界，而不是宣称文件 UI 的路径限制能约束 shell。

### 19.5 危险操作与运行边界

可执行路径和 argv 分离，不通过字符串拼 shell；环境变量使用允许策略且不在日志打印。诊断命令有超时、输出大小和并发上限。进程清理核验本产品持有的进程对象与身份，不按进程名批量 kill。卸载只处理本产品拥有的资源，不顺便删除外部工作树或关闭用户会话。

## 20. 非功能要求与性能预算

下表是**待实现、待测量的验收目标**，不是当前项目或竞品的测试结果。M0 记录 CPU、内存、OS、浏览器、DSH/Herdr 版本、数据集和采样方式；若需要调整，必须通过 ADR 写明理由，不在测试失败后悄悄抬高门槛。

| 项目 | 初始目标 | 测量边界 |
|---|---|---|
| 基准环境 | 4 核 CPU、8 GB RAM、本地连接、固定浏览器版本 | 分别测试宿主已就绪与冷启动，不混合计算 |
| 典型规模 | 20 工作区 / 100 panes；压力集 100 / 500 | 资源列表可大，实际打开终端数量受配额限制 |
| 总览可用时间 | p95 ≤ 2 秒 | 宿主/Herdr 已运行；不含安装与 Agent 冷启动 |
| 事件到界面 | 健康事件通道 p95 ≤ 1.5 秒 | 从 Host 收到事件到归一化状态可见；外部事件缺失另记 |
| 降级轮询 | 健康请求下约 5 秒一轮，状态可见 ≤ 10 秒 | 只作为降级；显示轮询状态而非声称实时 |
| 列表交互 | 常见筛选/展开交互 p95 ≤ 100ms | 500 panes fixture；长列表虚拟化或分页 |
| 终端本地输入反馈 | p95 ≤ 150ms | 从可发送输入到回显；排除 Agent 自身阻塞等待 |
| 终端实例 | 默认同页活跃 1—4，手机默认 1 | 后台视图降级，禁止总览自动开满 |
| Host 初始配额 | observer 8、controller 2、桥接进程 16；均可配置 | 每 pane controller 仍为 1；closing 计入占用 |
| 缓冲预算 | 按流限制字节/帧数，整体预算也有限额 | 超限重建或拒绝新观察；不能无限排队 |
| 高产出测试 | 至少 1 MiB/s、10 分钟的已知测试流 | 监测消费、UI响应和内存，不要求无限吞吐 |
| 长时运行 | 60 分钟切页/断连/重连，无持续增长的泄漏趋势 | 关注 GC 后趋势，记录浏览器/Host基线及峰值 |
| 卸载清理 | 正常路径 5 秒内停止本产品后台活动 | 未退出进程保留异常与配额，不假装清理完成 |
| 可访问性 | 核心流程 WCAG 2.2 AA 目标 + 人工键盘/读屏检查 | 终端不能只用静态 axe 扫描判定 |
| 视觉矩阵 | 两主题×两密度×关键容器宽度 | 375、768、1280、1920px，另加宿主实际槽位 |

服务端资源采样与轻量拓扑刷新分开调度；对昂贵进程树采样设置最小间隔。初始重连退避可采用 1/2/4/8/16/30 秒上限与随机抖动；明确取消、用户重试和页面卸载行为。健康事件场景用短合并窗口和最大刷新延迟，避免每事件一次完整快照。

首屏不导入 xterm、后续文件预览或所有模块的重依赖。构件预算按独立 chunk 记录并设置回归阈值；是否计入宿主已有 React/SDK 必须说明，不以扣除依赖后的数字误导真实下载成本。

## 21. 测试策略与关键验收场景

### 21.1 测试层次

| 层次 | 验证内容 | 不应取代的验证 |
|---|---|---|
| 领域单元 | 状态映射、归属、权限、排序、lease 状态机 | 真实协议与进程行为 |
| 契约测试 | 请求 schema、响应、错误、生成 arity | 仅编译成功不算真实调用成功 |
| 组件测试 | 表单、禁用原因、键盘、空态、错误态 | 真实 DSH 布局与 CSS 干扰 |
| 集成测试 | Herdr API、终端 attach、进程生命周期 | fake server 不算真实 Herdr 通过 |
| E2E | 打包安装、打开总览、创建、观察、控制、卸载 | 开发 dev server 测试不能代替 |
| 安全测试 | 越权、旧 lease、Origin、输入限制、注入、脱敏 | 依赖扫描不能代替业务授权测试 |
| 视觉/无障碍 | 亮暗、密度、窄屏、读屏、IME | Storybook 截图不能证明运行性能 |
| 压力/故障 | 突发事件、高产出、断线、清理失败、竞争 | 正常路径通过不能省略 |

既有测试按保护的行为分类保留。旧源码字符串断言应迁移成真实契约/行为断言，而不是为变绿而删掉风险覆盖。真实依赖缺失时，要求集成的 CI job 必须失败，不能默认 skip 后发布。[S09]

### 21.2 必须存在的 Given / When / Then 场景

| 场景 | Given / When | Then |
|---|---|---|
| 零参数/封装合同 | 打包后的真实描述符与生成客户端执行总览查询 | 参数个数一致且到达 Host，不在网关前失败 |
| 断流不清零 | 有有效 8 Agents 快照，collector 请求失败 | 保留旧 8 与 stale 标记，不显示“0 Agents” |
| 快照事件竞态 | 快照在飞时收到更新事件，随后旧读取返回 | 标 dirty 后再读，旧事件不能覆盖更晚权威状态 |
| events_lost | 订阅超出历史并关闭 | 新订阅确认后权威重读，历史缺口仍显示 |
| 资源替换 | 旧 pane ID 被新 occupant 复用 | 旧审批、关闭、input 被拒绝 |
| 控制竞争 | 两窗口同时请求控制同 pane | 至多一个成功，另一个得到冲突而非静默抢占 |
| 显式接管 | B 窗口确认接管 A 的控制 | A lease 撤销、停输；B 获实际 lease 后才能输入 |
| 双窗口存活 | A、B 都在观察，A 页面关闭 | B 连续观察；桥接按引用和宽限规则存活 |
| 进程退出失败 | bridge 未按期退出 | 继续计入配额，错误可见，不启动无限替代进程 |
| attach 连续性 | cursor 超过缓存或 generation 不同 | 完整重建，不给错误全帧+差量组合 |
| 输入结果不确定 | 输入已可能送达但网络断开 | 不自动重试，显示不确定并需用户核验 |
| 中文输入 | 使用拼音/注音组合输入后确认 | 仅发送最终文本；Enter 不提前提交 |
| 样式隔离 | 挂载/卸载模块、打开 Dialog/Popover | DSH 外部按钮/排版不变化，焦点正常恢复 |
| 模块清理 | 在活动观察时停用 Herdr 模块 | 无残留订阅/计时器；Herdr 原始 Agent 不被关闭 |
| 对话绑定缺失 | DSH 当前会话无有效绑定 | 写入拒绝，不改用全局聚焦 workspace |
| 只读越权 | 篡改前端请求直接调用 input/close | Host 拒绝并记录元数据审计 |
| 页面断点 | 所有关键状态在 375px 容器下展示 | 操作可达、目标可见、无错误横向溢出 |
| 非法终端输出 | 输出脚本样式文本、恶意链接与剪贴板控制 | 不执行脚本、不隐式读写系统剪贴板 |
| 创建部分成功 | 工作区已建、Agent 启动失败 | 展示已建资源，重试 Agent 不复制工作区 |
| 最终产物 | 干净环境安装发行 tgz | 无开发依赖泄漏、无缺失入口、可启用并正常卸载 |

### 21.3 证据产物

每个发布版本保存源码 SHA、锁文件哈希、支持矩阵、单元/集成结果、Playwright trace、关键截图、性能结果、构件 SHA256 与已知限制。证据必须指向同一构建产物，不用旧分支的截图证明新包正确。

本次已核验的 Actions success 是一个仓库状态事实，而不是以上完整新验收矩阵已经执行完成。[S04]

## 22. 重构实施顺序、切换与发布

### 22.1 分阶段交付

| 阶段 | 核心产物 | 完成门槛 | 依赖 |
|---|---|---|---|
| M0：冻结事实与决策 | 新项目身份、支持基线、现有行为清单、协议探测、风险登记 | 原始源码/CI 可追溯；独立化与首发边界明确 | 本文 |
| M1：平台与设计系统 | monorepo、核心/SDK、DSH adapter、UI 包、示例模块 | 依赖规则、样式隔离、第二模块扩展和生命周期测试通过 | M0 |
| M2：Herdr 只读闭环 | 环境、快照、能力、总览、工作区/Agents列表 | 真数据、partial/stale、事件恢复、缺失环境不白屏 | M1 |
| M3：安全操作与终端 | 创建/启动/关闭、绑定、lease、attach、回放、配额 | 真实 Herdr、多窗口、投递不确定与外部资源保护通过 | M2 |
| M4：完整管理体验 | 待处理、基本活动/审计、窄屏、键盘、诊断 | 全部关键异常状态和交互矩阵通过 | M3 |
| M5：发行 | 最终构件、安装/卸载、许可证、性能、使用文档 | 所有 P0 关闭或有经批准且明确不发行的裁剪；不能默默降级 | M4 |
| M6：扩展 | 聊天、历史、多主机、PWA/通知 | 每项独立能力、安全与体验验收 | 首发稳定 |
| M7：独立宿主/第三方生态 | 生产独立运行与受控第三方模块 | 完整身份、部署、隔离和供应链门禁 | 额外 ADR |

阶段顺序代表依赖，不是日程承诺。建议先交付一条贯穿平台到真实终端的最小闭环，再扩充页面，而不是先完成几十张无数据原型。

### 22.2 代码迁移方式

不在旧工程中长期并行两套公开 API。可在重构分支或新仓库逐步建立新结构，但最终发行只包含新入口。现有代码按职责归类：协议和进程约束提取为测试与适配实现；展示组件按新 UI 包重做；宿主 DOM patch 删除；旧数据仅备份，不做自动隐式迁移。

研发内部可以用旧版对照验证行为，用户运行时不保留“新失败就回旧”的分支。否则所谓不兼容重构会变成维护两套系统。

### 22.3 版本与发行

新产品初始版本可采用新的 major 起点，但具体名称、scope 与版本政策需在 M0 冻结。发行渠道先选一个明确主渠道；GitHub 构件可延续当前可靠打包思路，也可另行设计 npm 发布，但不能同时给出互相冲突的安装说明。

每次发布从同一提交构建一次，测试并发布同一产物；已发布版本不可覆盖。Actions 依赖应固定到审核后的 commit，权限最小化，发布 job 只能在质量/集成/构件验收通过后运行。记录 SBOM、许可证和校验文件。

### 22.4 切换与恢复

旧插件停止加载后安装新产品；新产品使用独立配置与显式连接。外部 Herdr 服务和已有工作区保持原状，用户选择观察或明确采纳；不按标签自动认领。若新产品验收失败，可卸载新产品并回到旧软件，但这属于部署回退，不是新旧 API 互相兼容。新版本自有数据恢复按其 schema 与备份处理，不能自动回灌到旧插件。

## 23. 架构决策记录、风险与待验证事项

### 23.1 建议 ADR 清单

| ADR | 决策 | 备选未采纳理由 |
|---|---|---|
| ADR-001 | 中立平台 + first-party 模块化单体 | 微服务/微前端增加部署、身份和状态一致性成本 |
| ADR-002 | DSH 是首发宿主 adapter | 立即完全独立运行需要新增认证/托管/部署，不是删依赖可完成 |
| ADR-003 | shadcn + Base UI + 自有 UI 包 | 多组件库混用会破坏视觉与键盘一致性；Ant 作为整体备选 |
| ADR-004 | 后端权威读模型，事件失效触发刷新 | 不假设外部快照/事件有可合并的统一边界 |
| ADR-005 | 终端独立流与控制 lease | 普通 query/store 不适合高频字节、背压和控制权 |
| ADR-006 | 元数据和业务动作契约单源 | 手写多份 DTO/描述符与参数例外容易漂移 |
| ADR-007 | 新产品不兼容旧插件 | 不引入 shim/双写；外部运行资源仍受保护 |
| ADR-008 | 首发仅可信构建期模块 | 同进程插件不是沙箱，不能直接开放任意安装 |
| ADR-009 | 默认不保存完整终端/对话 | 降低隐私、磁盘和凭据泄漏风险 |
| ADR-010 | 私有宿主 API 零依赖 | 没有公开槽位时降级，而不是继续 Fiber/DOM patch |

### 23.2 风险台账

| 风险 | 影响 | 对策与验证 |
|---|---|---|
| 目标 DSH 版本缺少预期公开槽位 | 部分宿主装饰无法实现 | M0 用发布版本验证；缺失时保留工作台内部展示 |
| React/构建格式与宿主不匹配 | hooks、模块加载、打包故障 | external/singleton 规则与最终产物 E2E |

| 调研项目文档夸大或过时 | 错误采纳不存在的能力 | 参考仅用于设计启发；落地前单项实机探针 |

## 24. 总体验收：什么才算重构完成

### 24.1 产品与架构

独立仓库与发行关系可验证；产品不再以 Herdr 名称污染所有平台层接口；可加入第二模块而不改壳层或 Herdr；核心无 DSH/Herdr 依赖；无私有 Fiber/DOM patch；旧兼容代码不进入产物；所有模块共享同一 UI、设置、命令与错误呈现机制。

### 24.2 Herdr 体验

首次使用能判断环境缺什么；总览能回答“哪里需要我”；列表/卡片/详情导航连贯；资源目标与新鲜度始终可见；unknown、blocked、done、disconnected 不混淆；不存在无数据伪图表或未经验证的任务进度；终端默认观察，显式取得控制才可输入。

### 24.3 安全与可靠性

每个敏感读取和写入在 Host 鉴权；两窗口控制、断线、重放、实例替换、慢输出、配额与清理均经过测试；关闭页面不杀 Agent；旧配置和外部工作区不自动删除；日志和导出不泄露 token/正文；同进程模块不被宣传为安全沙箱。

### 24.4 交付

89 项需求台账与对应验收有状态和证据；所有 P0 在发布范围内闭环；最终构件通过真实安装、启用、核心流程和卸载；README、支持矩阵、已知限制与实际提交/CI 一致。不能用“页面截图更好看”“类型检查通过”或“目录已经拆开”替代重构完成标准。

**最终建议：以平台边界与终端正确性为底座，以待处理优先的信息架构为中心，以统一 UI 包为治理手段，完成首个独立产品版本；之后通过模块扩展，而不是继续扩大 Herdr 单页。**

## 附录 C. 后续调研与验证应补的证据

后续实施不需要再广泛搜集几十张截图，而应围绕会影响决策的缺口补证：冻结 DSH 版本的槽位/身份/构建能力，选定 Herdr 版本的完整 schema 与终端探针，目标操作系统的真实进程清理，CJK 输入与移动软键盘，精确 Agent 会话映射，以及用户真实工作区数量和终端并发负载。

对候选项目进一步阅读时，统一记录仓库、commit、许可证、运行架构、输入通道、身份与权限、资源所有权、状态一致性、维护证据、实际试用结果；未实测的仍标“维护者声明”。新发现只有改变需求或取舍时才更新 ADR，避免把调研清单扩张当作产品进展。

## 附录 D. 术语表

| 术语 | 本文含义 |
|---|---|
| 宿主插件 | 安装到 DSH 的产品入口与适配包装 |
| 功能模块 | 工作台内部可注册、可停用、受治理的业务单元 |
| Herdr 原生插件 | 外部 Herdr 的 manifest/action/hook 机制，不等于工作台模块 |
| Workbench shell | 本产品导航、页面框架、设置和全局交互，不是 OS shell |
| Host | 执行业务与协议、权限、进程管理的服务端上下文 |
| pane / tab / workspace | Herdr 的终端资源层级 |
| DSH conversation | DSH 对话，不是 Herdr session |
| epoch | 当前服务或数据代次，用于拒绝旧实例引用 |
| lease | 本产品授予的有作用域控制租约，不保证排除所有外部客户端 |
| freshness / coverage | 数据新鲜度 / 数据完整覆盖程度 |
| capability | 经服务端判断的可用能力/权限，不是前端自报权限 |
| P0 / P1 / P2 | 首发门槛 / 后续增强 / 需额外架构的扩展 |
