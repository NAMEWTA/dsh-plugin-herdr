# Workbench 1.0.4-alpha.1

**补丁预览版。** 从已发布的 `1.0.3-alpha.1` 起，数字 patch 加 1，后缀仍是 `-alpha.1`。只发 GitHub prerelease，不发 npm，不覆盖 `v1.0.3-alpha.1` 或更早的 Release。

宿主基线仍是 **DSH 0.2.1-rc.2** 与 **Herdr 0.9.3 / protocol 22**。

## 这次改了什么

### 会话项目路径自动成为该会话的工作区

新建会话后，第一次调用本插件的任何 Herdr 工具时，如果这个会话还没有绑定，就用服务端会话头里的项目路径创建或复用工作区并绑定。来源记为「工具创建」。右侧栏在同一条路径上自动做同样的事，来源记为「界面创建」。空态「此会话还没有工作区」只在确实没有项目路径时出现。

不会改用当前聚焦的工作区。已有的有效绑定不会被另一条路径替换。只读身份不能创建。路径必须是批准根目录内的绝对目录。跨会话、绑定工作区之外的资源仍然拒绝。

### 启动 Agent

新增 `workbench_herdr_launch`。一次调用可以启动多组 Agent，总数 1 到 8。`codex` 运行 `codex`，`claude` 和 `claude-code` 都运行 `claude`。`send` 只能是 `false` 或省略，不接受 prompt、text、message、keys、content。工具说明里带有参数示例。校验失败会指出字段和期望格式。启动结果返回 name、paneId、terminalId、tabId、workspaceId，并写入会话台账。人工批准仍由 DSH 弹出，不放进模型参数。

`workbench_herdr_action` 继续用于重命名、关闭、拆分和新建标签页。它不再是启动 Agent 的入口。

### 错误

没有项目路径时返回 `INVALID_REQUEST`，并说明要在项目目录打开会话，或在工作台会话页手动绑定。只读、跨会话、根目录外、绑定范围外仍然是 `FORBIDDEN`，错误里写明原因。Herdr 协议错误保留服务端原文，不再只剩一个错误码。

## 真机与自动化

集成测试使用真实 Herdr 0.9.3：新会话第一次工具调用自动绑定，一次启动 4 个 codex 和 4 个 claude（本机没有对应程序时用保持运行的 shell 占位，仍走 Herdr 协议），再对另一个会话连续启动 8 次，并核对台账。浏览器夹具覆盖右侧栏自动出现工作区。物理中文输入法、读屏器、macOS 和原生 Windows 仍未宣称通过。

## 已知限制

- 空会话（Into the Unknown）不挂载页头操作槽。「终端 N」要等会话离开 blank。右侧栏在有项目路径时会先绑定。
- 同一路径上有多个工作区、且没有唯一同名标签时，会新建工作区，不会猜当前聚焦的那一个。
- 给模型的工具说明仍是英文。批准框的用户可见文案是中英对照。
- 这不是稳定版，也不是 npm 发布。

## 安装

核对环境：**Linux x86_64、Node 24.22.0、pnpm 10.28.2、DSH 0.2.1-rc.2、Herdr 0.9.3 / protocol 22**。

```sh
sha256sum --check SHA256SUMS
dsh plugin --profile web remove @namewta/dsh-workbench
dsh plugin --profile web add /absolute/path/namewta-dsh-workbench-1.0.4-alpha.1.tgz
```

然后重启正在运行的 DSH Web，并重新加载已打开的标签页。首次安装可以省略 remove。替换插件不会删除外部工作区，也不会停止 Agent。

`build.json` 标明这次 main 验收的源码 SHA。三项 main 检查都通过后，CI 才发布这一版；tag 已存在时不会覆盖。
