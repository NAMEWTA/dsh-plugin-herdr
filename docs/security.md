# 安全模型

Workbench 是真实终端的控制面。取得控制权意味着可以以运行 Herdr 的用户权限执行程序；此产品不是 shell 沙箱、不是多租户服务，也不能依靠“危险命令黑名单”保护宿主。

## 身份与边界

DSH 负责 HTTP/WebSocket 的认证、会话与 Origin 准入。适配器只接受 `ctx.invocation.peer.id`，不接受浏览器自行提交的 actor、role 或 scope。所有读取、写入和流消息均继续服务端验权。实际 DSH 网关的匿名/跨 Origin 拒绝在 `tests/e2e/dsh.mjs` 中验收。

每个 Workbench 面板获得独立随机客户端能力；生命周期由事件流、过期和显式断开控制。终端另有独立随机租约，只返回给所属客户端，不放进 URL。失去流时撤销控制，其他窗口的观察流不受影响。没有共享的全客户端终端广播。

DSH 原生启动 URL 可能含一次性交换 token，这是外部宿主的机制，不属于 Workbench 发出的永久链接。测试日志会脱敏；Workbench 自身不增加 URL token。不要把整个宿主启动输出或 profile 上传排障。

## 资源与进程

名字不是所有权。外部资源默认只能观察，显式接管只授权当前实例，不隐式授权子资源。工作区/窗格关闭与释放观察不同。卸载、停用、重启页面不会自动关闭外部 Agent 或 Herdr daemon。

配置二进制是管理员可信输入，必须明确路径/版本。新建工作区路径经过 realpath 根目录限制；Agent 使用批准的 kind，固定 argv，不用 shell 拼接。原始终端输入本来就是用户授权的 shell 控制，不可误称为已被同一 allowlist 限制。

## 浏览器输出与存储

终端由 xterm 按字节解析，不把输出当 HTML；不安装自动网页链接扩展，拦截 OSC 52 剪贴板控制。复制是用户显式动作，粘贴需确认，换行不会被静默补加。未知状态和来源缺失不会被伪装为成功。

普通 React 文本保持转义；首发没有 Markdown/文件预览功能。不要后续加入 `dangerouslySetInnerHTML` 或自动执行终端链接而不增补威胁模型。

Host 数据目录/文件分别使用 0700/0600，拒绝符号链接和坏 JSON，CAS/排他锁防止覆盖。审计只保留请求、目标实例、时间和结果元数据；actor/client 散列化，原始输入、输出、环境变量和凭据不记录。导出默认排除路径与正文，并先预览。

## 部署限制

只在受信设备和私网使用。宿主 HTTP 端口的公开暴露、跨用户共享 HOME、被盗浏览器 profile、恶意已授权终端或恶意第一方代码不在安全隔离保证内。第一方模块必须代码审核；任意第三方模块需要额外隔离设计。

见 `docs/acceptance.md` 的尚未验证项。零 axe 违规或单元测试通过不等同于完整安全审计。
